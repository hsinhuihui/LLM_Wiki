# 合併衝突排查與解決：標記語法與標準處理流程

當兩個不同的分支同時修改了「同一個檔案中的相同行數或區段」時，Git 無法猜測哪一個版本才是正確的，這時就會暫停合併，進入「衝突狀態（Merge Conflict）」。

---

## 概念圖解與比喻 (Visual Analogy)
> **衝突不是程式出錯，而是 Git 在向你請示決策。**
> 就像兩位編輯同時修改了合約的同一條款，Git 不會武斷覆蓋任何一方，而是將兩份內容都保留下來，並用特殊標記框住，請主編手動確認最終保留版本。

---

## 核心觀念 (Core Concept)

### 1. 衝突標記結構 (Conflict Markers)
當衝突發生時，Git 會在衝突檔案內注入標準標記：

```text
<<<<<<< HEAD
當前所在分支（例如 master）的程式碼內容
=======
被合併分支（例如 iss53）的程式碼內容
>>>>>>> iss53
```

- `<<<<<<< HEAD` 到 `=======` 之間：代表目前所處分支的原始內容。
- `=======` 到 `>>>>>>> iss53` 之間：代表嘗試合併進來的新內容。

### 2. 標準解決步驟
1. **定位衝突檔案**：輸入 `git status`，查看列在 `both modified:` 或 `Unmerged paths:` 底下的檔案。
2. **手動編輯檔案**：
   - 開啟衝突檔案，人工決定保留上方、保留下方，或是重新整合兩者。
   - **徹底刪除所有的 `<<<<<<<`、`=======`、`>>>>>>>` 標記行**。
3. **標記為已解決**：使用 `git add <檔案名稱>` 將檔案加入暫存區（在 Git 中，對衝突檔案執行 `git add` 即代表「衝突已解決」）。
4. **完成合併提交**：執行 `git commit`（無需額外加 `-m`，Git 會自動生成預設的合併說明），完成 Merge Commit。

---

## 常用指令與操作 (Key Commands)

```bash
# 1. 嘗試合併分支時發現衝突
git merge iss53
# 終端提示：CONFLICT (content): Merge conflict in index.html

# 2. 檢視未合併的衝突檔案清單
git status

# 3. 手動開啟並修改檔案、移除標記後，標記已解決
git add index.html

# 4. 完成合併提交
git commit

# 輔助：使用視覺化工具輔助比對衝突（可選）
git mergetool

# 救援：若情況過於複雜想放棄這次合併回到原狀
git merge --abort
```

---

## 常見誤解與排查 (Gotchas & Troubleshooting)
- **誤解：忘記刪除衝突標記就 commit！**
  - 如果沒刪除 `<<<<<<<` 或 `=======` 就執行 `git add` 與 `commit`，語法錯誤標記會直接被編譯進正式程式碼中，導致線上系統報錯。
- **取消合併**：如果發現衝突過多難以在當下解決，可隨時輸入 `git merge --abort` 乾淨退回合併前的狀態。
