# 三個神秘空間：工作區、暫存區與儲存庫

Git 之所以讓很多初學者感到困惑，是因為它不是按下「儲存」就直接把所有東西丟進歷史紀錄，而是設計了三個貼心的「安全緩衝區」。

---

## 🎨 繪本隱喻 (Visual Metaphor)

想像你是一位在童話森林裡開畫室的小動物畫家：

1. **工作區（Working Directory）＝ 雜亂的草稿畫桌 🖍️**
   - 這裡放著你正在畫、正在修改的所有半成品。你可以隨便畫錯、橡皮擦擦掉，沒有任何壓力，Git 不會主動干涉你在桌上塗鴉。
2. **暫存區（Staging Area / Index）＝ 準備拍照的展示台 📸**
   - 當你畫好了幾張滿意的草稿，你把它們整齊地擺到特別的「展示台」上。這代表：「**嗨 Git 攝影師！我等一下只想拍這幾張，其他還沒畫完的先留在畫桌上就好！**」
3. **儲存庫（Repository / Git Directory）＝ 永恆的拍立得時光相簿 📖**
   - 攝影師按下快門（`commit`），展示台上的畫作被拍成一張無法塗改的拍立得照片，貼上時間戳與備註，整齊收進相簿。即使畫桌以後燒掉了，你也可以隨時從相簿還原！

---

## 💡 核心觀念 (Core Concept)

- **為什麼不能直接從工作區存檔？為什麼要多一個「暫存區」？**
  - **精準挑選**：有時候你同時改了 5 個檔案，但其中 2 個是修錯字，另外 3 個是未完成的新功能。暫存區讓你可以只挑修錯字的檔案進行拍照存檔，保持歷史紀錄乾淨俐落！
- **檔案的三種狀態**：
  - `Modified`（已修改）：只在畫桌上動過筆。
  - `Staged`（已暫存）：已經放到拍照展示台上（透過 `git add`）。
  - `Committed`（已提交）：快照已經安全存進相簿裡（透過 `git commit`）。

---

## ⚡ 常用指令與咒語 (Key Commands)

```bash
# 1. 看看畫桌與展示台的現況（有什麼東西在展示台上？有什麼東西還在桌上？）
git status

# 2. 把滿意的檔案請上展示台
git add index.html
git add .    # 把桌上所有修改過的畫稿一次請上展示台

# 3. 按下快門，拍照封存！
git commit -m "繪製小貓主角的首頁草圖"
```

---

## 🛟 新手容易踩的雷 (Gotchas & Traps)

> [!WARNING]
> **「我明明已經 `git add` 了，為什麼再修改檔案後 `git commit`，剛才補畫的內容沒有存進去？」**
> 
> **解答**：因為展示台拍照時，只會拍「你當時放上去那一瞬間」的模樣！如果你放上去展示台之後，又跑回畫桌偷偷添了兩筆，記得要**再次執行 `git add`** 重新把最新畫作請上展示台喔！
